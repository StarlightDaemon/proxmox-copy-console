# Repository review and proposed refinements

Reviewed 2026-09-18. This is a review and proposal, not an accepted design or an implementation of 0.4.0. The documented 0.3.0 baseline remains unchanged.

Subsequent implementation status: the user authorized development after this review. The root source is now `0.4.0-dev.1`; this report remains the historical assessment of commit `27a83d2`. See [Research](RESEARCH.md), [Design](DESIGN.md), and [Testing](TESTING.md) for the implemented choices and current evidence.

## Scope and conclusion

Reviewed all nine tracked files in `StarlightDaemon/proxmox-copy-console`, on local `main` at `27a83d2ac836ef35c2f7e6644b6e448355631be0`. The origin is `https://github.com/StarlightDaemon/proxmox-copy-console.git`. The checkout was clean before this report. Local history contains three commits; history metadata was inspected, but this was not a forensic scan of every historical blob or a remote repository settings audit.

The implementation is one 601-line userscript, 12,846 bytes in Git, with no packaged dependencies, build step, network calls, or persistent storage. The architecture fits the job. Keep it as one directly installable file. The best next iteration improves confidence in what gets copied and when copying succeeds; it does not need a framework, settings panel, or broader terminal integration.

No high- or critical-severity security issue was established in this review. There is a meaningful trust-scope hardening opportunity and a possible confidentiality consequence when the wrong console is selected. Several ordinary correctness and compatibility issues are reproducible with mocks. Actual Proxmox/browser/userscript-manager acceptance remains outstanding.

## Intended use and invariants

An administrator opens an embedded node Shell or LXC xterm Console in the main HTTPS Proxmox UI, then explicitly clicks a native ExtJS Copy button to capture retained output for troubleshooting or sharing. Normal shell copying includes scrollback; an active alternate-screen application contributes its current alternate buffer. This is a rendered terminal-text snapshot, not a lossless session recording or a recovery mechanism for discarded scrollback.

Preserve these decisions:

- One ordinary native button, immediately after the relevant console control, with stable text and native layout.
- Explicit copying from the retained buffer. The abandoned selection-event approach stays abandoned.
- Fresh terminal resolution when copying, including after reconnects and navigation.
- Normal/alternate buffer distinction and logical reconstruction of soft-wrapped rows.
- No server modifications, shell execution, clipboard reading, telemetry, or persistent transcript history.
- Minimal permissions and zero runtime dependencies. Current scope is embedded node Shell and LXC Console; noVNC/SPICE and standalone console windows are not established targets.

## Security assessment

The important boundary is: page-owned ExtJS and accessible iframe/xterm objects provide content to a userscript that can write the OS clipboard. The Proxmox page and userscript manager must be trusted. Terminal output itself can be untrusted.

The source does not evaluate terminal content, interpolate it into HTML, transmit it, read existing clipboard content, or request a privileged network API. Feedback contains fixed messages and counts, rather than transcript text. There are no embedded credentials apparent in the nine current tracked files. These observations do not certify the host page, installed extensions, upstream update channel, or historical secrets.

**S1 — Broad execution scope and a page-callable clipboard path.** Metadata line 6 enables the script on every HTTPS host at port 8006. Lines 540–559 pass a privileged copy handler to page-owned ExtJS. A matching page can supply the expected objects and invoke that handler programmatically; an actual human click is a usage convention, not an enforced security boundary. The mock demonstrated handler invocation without a DOM user event and regex matching of an unrelated host. A real userscript-manager exploit was not executed. The consequence would be clipboard replacement, not clipboard reading or cross-origin Proxmox access.

Recommended low-cost response: document manager-level restrictions to the user's exact trusted Proxmox hosts as part of installation, with examples for DNS names/IPs and explicit port 8006. Keep broad matching clearly disclosed. Do not add universal port-443 or wildcard reverse-proxy support. A `PVE`/`Ext` presence check can prevent accidental activation but cannot authenticate a hostile page. Changing the distributed default to require host configuration is a separate usability decision. Restricting origins is more useful than a naive `event.isTrusted` check on objects delivered through page-owned ExtJS.

**S2 — Console association is a confidentiality concern.** See R1. When more than one eligible frame/control is present, selecting the first frame can put another console's retained text on the clipboard. This is a conditional data-selection failure; no actual Proxmox disclosure was observed.

**S3 — Retained output can contain sensitive text by design.** Add one short README sentence explaining that Copy includes offscreen retained output and users should inspect it before sharing. Do not silently redact, normalize, or upload it. Automatic clipboard clearing could overwrite a later unrelated user copy and is not proposed.

## Findings in the current implementation

Line references below refer to the unchanged 0.3.0 `proxmox-copy-console.user.js`. P2 means a normal-priority correctness/compatibility fix; P3 means a smaller usability or efficiency refinement. They are not vulnerability severity scores.

| ID | Priority | Location | Evidence and impact | Smallest useful response |
| --- | --- | --- | --- | --- |
| R1 | P2 | 100–153, 358–410, 484–520, 551–559 | Terminal discovery and toolbar discovery are independent global searches. A mock with an LXC terminal and unrelated visible Shell control installs on the Shell toolbar. Two visible terminals are chosen by document order. | Resolve a console context tying together owner, frame, toolbar, and anchor. On click, reacquire the terminal within that context; refuse ambiguous ownership instead of choosing another console. |
| R2 | P2 | 276–299, 358–360, 540–571 | Terminal extraction occurs before the clipboard `try`. A throwing `getLine()` escapes the click handler, so feedback never reports failure. Component query/create/insert also have uncovered failure paths. | Catch at the copy and install operation boundaries. Distinguish unavailable, empty, and failed extraction. Dispose of a newly created button if insertion fails. Rate-limit repeated install warnings. |
| R3 | P2 | 175–186 | `/\s+$/u` removes actual Unicode whitespace as well as ASCII terminal padding. A row containing `value\u00a0` plus padding copies as `value`. | Narrow the existing cleanup policy to ASCII spaces and document it. This still is not byte-exact trailing-space preservation; cell-aware fidelity would be a separate, larger policy. |
| R4 | P2 | 358–374 | Anchor lookup recognizes only English labels. A visible `Konsole` button is rejected in the mock. Upstream uses translated labels. | Prefer Proxmox's console button type and supported `consoleType`, scoped to the same console owner. Use a guarded translated-label fallback only if a tested version requires it. |
| R5 | P2 | 299–317 | Success is returned immediately after invoking `GM_setClipboard`. A mock with a pending asynchronous write still reports success. Real manager completion/failure behavior has not been tested. | Define support for a concrete manager/browser first. Where a completion signal exists, wait for it before success feedback. Treat a legacy void return as dispatch evidence, not independently verified OS clipboard contents. |
| R6 | P3 | 436–481 | Every activation starts another reset timeout. The first timeout can clear the feedback from a later click early. Reproduced with deterministic timers. | Keep one pending feedback reset per button, cancel/replace it, and clean it up on destruction. Handle stale completion ordering too if copying becomes asynchronous. |
| R7 | P3 | 100–153, 484–599 | Discovery can inspect a frame twice, searches all ExtJS buttons every eligible tick, and has no document-hidden guard. Hidden-page installation is reproduced. No browser CPU bottleneck was measured. | Skip scans while hidden, rescan immediately on visibility return, narrow the component query, and reuse visibility checks within a single pass. Retain simple periodic recovery. |

R1's real-world trigger frequency and R5's manager-specific effect still require runtime verification. Mocks establish those decision paths, not a deployed incident. R2's extraction failure was exercised; its other uncovered boundary calls were identified statically.

The first Unicode cleanup improvement is deliberately small. Wide-character wrapping at the last column, emoji, combining characters, retained rows after resize, and a scrollback boundary beginning mid-wrap need real xterm fixtures before claiming full Unicode fidelity. The [xterm line API](https://xtermjs.org/docs/api/terminal/interfaces/ibufferline/) documents wrapping and column-range behavior; the [cell API](https://xtermjs.org/docs/api/terminal/interfaces/ibuffercell/) distinguishes display width from character content. These edge cases are test requirements, not confirmed defects from this review.

## Upstream checks and implementation direction

Current upstream [ConsoleButton.js](https://raw.githubusercontent.com/proxmox/pve-manager/master/www/manager6/button/ConsoleButton.js) exposes `pveConsoleButton`, `consoleType`, `nodename`, and `vmid`, with translated Console text. [Node configuration](https://raw.githubusercontent.com/proxmox/pve-manager/master/www/manager6/node/Config.js) supplies translated Shell text and `consoleType: 'shell'`. [LXC configuration](https://raw.githubusercontent.com/proxmox/pve-manager/master/www/manager6/lxc/Config.js) supplies `consoleType: 'lxc'` and the guest identity.

This supports trying a narrow `pveConsoleButton` query and owner/identity association. It does not prove those fields or containment relationships across all Proxmox releases. Validate against the actual target installation before removing fallbacks. Use containment first where possible; if comparing frame URL parameters, parse them with `URL` and compare exact node/type/guest fields rather than substring matching. Keep inaccessible-frame handling and Firefox's wrapped-object path.

[Tampermonkey documents](https://www.tampermonkey.net/documentation.php?locale=en&q=GM_setClipboard) a completion callback for the legacy function and an awaitable modern API. [Violentmonkey documents](https://violentmonkey.github.io/api/gm/#gm_setclipboard) a legacy clipboard call with a default plain-text MIME type. These contracts differ enough that an unconditional callback wrapper could itself break copying. Keep the currently unspecified clipboard type until the chosen support matrix validates an explicit form; no HTML clipboard injection was established here.

## Proposed implementation sequence

All behavior changes below are proposed future/unreleased 0.4.0 work. They are not additions to the accepted 0.3.0 decisions.

| Order | Work package | Estimated size | Completion criteria |
| --- | --- | --- | --- |
| 1 | Establish a reproducible baseline and installation trust guidance | Small; development/docs only | Record one real Proxmox/browser/manager combination. Preserve a 0.3.0 fixture/output comparison. Document trusted-host restrictions and retained sensitive output. |
| 2 | Fix console context and localization together (R1, R4) | Medium; highest integration risk | Node and LXC buttons target their own frame after navigation/reconnect. Localized labels work. Hidden/unrelated frames and ambiguous contexts cannot cause a wrong-console copy. |
| 3 | Tighten copy/error/feedback behavior (R2, R3, R5, R6) | Small to medium | Extraction failures leave clipboard untouched and show useful feedback. Unicode whitespace survives the chosen cleanup policy. Clipboard completion behavior matches the supported manager. Rapid clicks and destroyed buttons are safe. |
| 4 | Reduce idle work without changing architecture (R7) | Small | Hidden pages perform no discovery work; returning runs discovery promptly. Idle scans never read buffer rows. Foreground navigation remains responsive. Compare actual browser traces before claiming a performance gain. |
| 5 | Apply repository conventions and record acceptance | Small; development/docs only | Syntax, regression probes, link/metadata checks, and documented manual scenarios pass. README support/evidence table matches actual results. Version and changelog stay consistent. |

Use separately reviewable changes. Keep the 500 ms foreground interval initially; arbitrarily slowing it can make installation feel unreliable. Do not replace polling with a whole-document MutationObserver: terminal output can produce frequent DOM changes and lifecycle complexity. Do not cache a terminal across clicks or add asynchronous chunking without evidence that the real retained buffer causes noticeable stalls.

## High-value features for little addition

These are ranked candidates, not a commitment to include all of them.

| Rank | Feature | Value | Cost and boundary |
| --- | --- | --- | --- |
| 1 | Show copy scope in feedback, such as `Copied 42 lines · alternate screen` | Makes alternate-screen behavior understandable | Very small; `alternateScreen` already exists. Keep Copy text stable and avoid adding terminal content to tooltips. |
| 2 | Restore focus to the same terminal after a successful explicit copy | Lets an administrator continue typing immediately | Small; call the terminal's focus API only after confirming the original owner/frame remains active and the user has not moved elsewhere. Requires real browser keyboard and focus checks; do not steal focus after delayed completion. |
| 3 | Disable an existing Copy button when its own console becomes unavailable | Explains stale toolbar controls during tab changes or reconnects | Small once context resolution exists. Re-enable on recovery. An empty but available console should still return clear empty feedback. |
| 4 | Optional explicit Copy viewport action | Helps share a short visible excerpt without all retained history | Medium. Defer from the first refinement batch. Define scrolled viewport versus live bottom screen and wrapped-edge clipping; do not reuse full-buffer trimming blindly. A modifier-click saves UI space but needs discoverability and a keyboard-accessible equivalent. |

Localized toolbar discovery is included in the core fixes rather than marketed as a new copy mode. Do not introduce automatic select-to-copy, global Ctrl+C interception, transcript history, regex redaction, ANSI/HTML export, clipboard preview dialogs, or download/upload infrastructure in this iteration. Those features broaden the product and verification burden disproportionately.

## Repository standardization

- Add `.editorconfig`: UTF-8, four-space indentation, final newline, LF. Preserve intentional Markdown hard breaks. Add `.gitattributes` with a deliberate text/LF policy; Git blobs are LF but this Windows checkout currently uses CRLF. Keep any resulting normalization separate from behavior changes.
- Retain the single IIFE, ordinary JavaScript, and direct userscript installation. No TypeScript migration, bundler, package dependency tree, or generic adapter framework is needed.
- Use normal compact formatting for simple expressions and centralize repeated tooltip/icon strings. Preserve comments explaining wrapping, Firefox exposure, and lifecycle decisions. Avoid a large formatting-only rewrite while fixing behavior.
- Add a small development-only regression harness using Node built-ins. Test through the installed button handler where practical; a narrowly documented VM export seam can exercise extraction without shipping test globals. Do not duplicate the extraction algorithm in tests.
- Add one minimal CI check when implementation begins: syntax, regressions, metadata/version consistency, and repository-local documentation links. Keep workflow permissions read-only and external actions pinned. No coverage quotas or dependency update bot are useful until dependencies exist.
- Extend `docs/TESTING.md` with a compact dated evidence table: source commit, Proxmox version, bundled xterm version if known, browser, userscript manager, scenario, actual result, and limitations. One verified setup is more useful than implied support for every manager.
- Keep README for installation/usage/support, DESIGN for behavior, DECISIONS for accepted rationale, HISTORY for lineage, and CHANGELOG for releases. Replace repeated evidence caveats with links where practical. Correct README's abbreviated algorithm to mention completed-line cleanup as well as trailing empty rows.
- Add `@license MIT`, `@homepageURL`, and `@supportURL` only with verified project destinations. Preserve `@name` and `@namespace` to avoid changing userscript identity. Do not silently introduce auto-update URLs as metadata cleanup.

No missing framework, package manifest, lockfile, or build system is itself a repository defect. The existing MIT license is present, and the project documentation consistently labels 0.4.0 as future work.

## Verification performed

Executed locally on Node v24.18.0:

- `node --check proxmox-copy-console.user.js`: passed.
- An ad hoc VM harness executed the actual source with an in-memory export seam and mocked browser, ExtJS, buffer, clipboard, and timer objects: **22 of 22 assertions reproduced their expected observations**. Twelve checked baseline behavior, eight reproduced limitations, and two checked trust-scope hardening cases. This is not a claim that 22 acceptance tests passed or that the defects are fixed.
- Baseline observations covered wrapped interior spacing, blank-row cleanup, normal/alternate buffers, hidden and inaccessible frame filtering, wrapped-object discovery, fresh terminal resolution, empty-copy handling, synchronous clipboard errors, duplicate prevention, and subframe exclusion.
- Limitation observations covered Unicode whitespace trimming, extraction exceptions, translated labels, unrelated toolbar association, multiple visible terminals, overlapping feedback timers, immediate asynchronous success reporting, and hidden-document scanning.

The ad hoc harness is a local review artifact outside the repository; it is not a committed regression suite. Its clipboard mock never accessed the OS clipboard. Its wrapped-object and cross-origin simulations do not establish Firefox compartment behavior or browser origin enforcement.

All nine current files were read. Upstream documentation/source checks informed the API recommendations above. The Claude Security workflow could not run because its required Workflow tool is unavailable; this is a direct review, not a Claude Security scan or independently panel-verified report.

Not performed: live Proxmox execution, browser automation, real xterm Unicode/resize experiments, real userscript-manager clipboard writes, manual acceptance, CPU profiling, GitHub settings/branch-protection inspection, or a historical secret scan. No implementation change, commit, remote update, PR, release, or deployment was made by this review.

## Release acceptance gate for the proposed work

Before a future 0.4.0 release, capture actual clipboard output for node Shell and LXC Console, including scrollback beyond the viewport, interior blank lines, wrapped spacing, Unicode whitespace, CJK/emoji/combining characters, resize/reflow, and alternate-screen entry/exit. Verify navigation, reconnect, localized controls, unrelated/multiple/hidden frames, hidden-tab return, rapid repeated clicks, destruction during pending feedback, extraction errors, and clipboard failure/completion behavior.

Compare expected strings rather than only screenshots or a success icon. Record exactly which browser/manager/version was exercised. Keep unsupported surfaces explicit. A mock result or a source-level API match cannot substitute for this gate.
